# Ruled out

Options that are off the table. Three reasons: a hard constraint from [criteria.md](criteria.md) fails, public evidence contradicts the option's warrant, or the option reverses a completed migration and never had an advocate. The last column says what returns it; "nothing short of new evidence" means no design argument reopens it, only a fact that contradicts the warrant.

| Option | Why it's out | What would bring it back |
|---|---|---|
| **`init()` registration with blank imports** | Production registration by `init()` has been removed twice: from this subsystem in PR #28933, and separately from sweepers, which now use an explicit `RegisterSweepers()` calling `awsv2.Register(...)`. All 52 remaining `func init()` in `internal/service` are in `_test.go`; none in production ([provider-contract](../findings/provider-contract.md), [history](../findings/history.md)). Proposing it reverses both migrations. | A project decision to reverse direction. The stdlib precedent (`database/sql`) is real, so this is an argument about direction, not about Go. |
| **Package-level registration variable** (`var _ = gen.Resource(...)`) | Package-level state assigned by a function call, the same objection as `init()`, plus it needs a build tag to avoid running at startup. Under that tag gopls and `go vet` skip the file, removing its only advantage, the real Go references that rename and find-references can see. Zero instances; nobody proposed it. | Nothing short of new evidence. |
| **`ResName` constants as a registration mechanism** | The 1,853 occurrences across 340 files are error-message constants in the legacy `create.Error(...)` pattern, a subsystem smarterr/smerr is replacing. They were never a registration mechanism; they were listed only because they hold a friendly name. | Nothing short of new evidence. |
| **Leave the annotations exactly as they are** | Fails *Fails early, locally, and never inertly*: unknown keys land at "never" (live at `elasticache/reserved_cache_node.go:37`) and inert opt-outs sit unread ([silent-failures](../findings/silent-failures.md)). | Add machine-checked keys and liveness checks. That turns it into tidy-in-place, which survives the filter, so it returns as a different option, not this one. |
| **Replace every resource at once (big bang)** | Fails *Migrates incrementally*: 2,670 files and every consumer changed together, with no coexistence path or fallback. | A coexistence design where old and new forms run side by side. With one it is no longer big bang. |
| **Per-resource entries in `names_data.hcl`** | Fails *Resource-scoped work stays complete and fast*: registering a resource needs full `make gen` instead of the scoped loop (about 5 s for `ecs`), because the file is central ([registration](../findings/registration.md)). | A way to register a single resource without regenerating the whole provider. |
| **Ask the constructed instance as the only mechanism** | Fails *Serves every consumer*: generators run before the provider starts and cannot read a constructed object, and there is no instance for the 1,754 SDKv2 registrations at generate time ([provider-contract](../findings/provider-contract.md)). | Pair it with split-by-framework and a runtime test harness. On its own it does not serve the generators. |
| **Name resources from `runtime.FuncForPC`, or only inside the factory body** | Fails *Serves every consumer*: the names exist only at runtime, but generators need them at generate time for test files and fixture paths. | Generators that never need the name at generate time. None exists today. |
| **Any serialized format carrying references to Go symbols** (HCL or other spec forms naming a Go type, function, or field) | The design requires a checked Go reference for anything naming a Go symbol, so a string copy is refused ([spec-or-metadata](../../concepts/spec-or-metadata.md)). Supporting evidence: `controller-gen` silently ignores misspelled marker keys at far larger scale ([controller-gen](../../case-studies/controller-gen.md)), and the provider's own `tagsTests` typo sat unreported from March 2023 ([silent-failures](../findings/silent-failures.md)). | A proposal that argues against the checked-reference principle directly, or evidence that such a format fails loud on a stale symbol. |
| **`tfplugingen` / Provider Code Specification as the annotation replacement** | Its scope excludes registration, test policy, identity, and lifecycle, which is the whole problem ([tfplugingen](../../case-studies/tfplugingen.md)). It has been tech preview for three years with no component release in 25 months, and every observed adopter uses it for schema and models while hand-writing behavior. | Nothing short of new evidence: scope expansion plus active releases. `tfplugingen-framework` stays alive narrowly as a scoped experiment on a new schema-heavy Framework family, which is a different question. |
| **One universal `ResourceSpec` holding every concern** | Magic Modules already ran this experiment: about 90 fields, eleven `exclude_*` switches, single-use keys, a hand-written escape hatch ([spec-or-metadata](../../concepts/spec-or-metadata.md)). A typed version is the same attractor with autocomplete, and the admission rule refuses it ([vocabulary-governance](../../concepts/vocabulary-governance.md)). | Nothing short of new evidence. |
| **"Every generator learns every authoring representation" as the migration mechanism** | Presumes a burden that does not exist. The three generators that consume annotations already share a common identity layer; extend that layer instead ([shared-implementation](shared-implementation.md)). | Evidence the shared layer cannot carry a new representation. |
| **A single authored surface per resource owning all its facts** | Rejected as an *authority*. The real requirement, seeing one resource's knobs in one place, is met by a [generated report](resource-report.md), a *view*, not by consolidating authorship ([discovery-and-placement](discovery-and-placement.md)). | Not applicable: the need is already served by a view. |
| **Dynamic resource loading via Go's `plugin` package** | Go's `plugin` package does not support Windows, and the provider ships Windows builds. | Nothing short of new evidence: Windows support landing in Go's `plugin` package. |
