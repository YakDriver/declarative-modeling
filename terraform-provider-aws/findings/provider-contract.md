# Provider Contract

What the running provider consumes from each registration at startup, and what any replacement of the authoring mechanism must keep producing. Counts from this repository on 2026-10-01, independent of how registration data is authored.

## Startup path

```text
main → provider.ProtoV5ProviderServerFactory (internal/provider/factory.go)
  ├─ sdkv2.NewProvider: servicePackages(ctx) from service_packages_gen.go
  │    initialize(): SDKResources/SDKDataSources → wrap → ResourcesMap[TypeName]
  │    AWSClient.SetServicePackages(map[name]ServicePackage)
  ├─ framework.NewProvider: same set, from the SDKv2 provider's AWSClient
  │    initialize(): FrameworkResources/DataSources, EphemeralResources,
  │                  ListResources, Actions → newWrapped…(spec, name) closures
  └─ tf5muxserver.NewMuxServer(SDKv2, Framework)
```

Ephemeral, list, and action kinds are optional interfaces, detected by type assertion on the service package.

## The service package list

`internal/provider/sdkv2/service_packages_gen.go` (568 lines, generated by `internal/generate/servicepackages`) imports every service package and returns `[]conns.ServicePackage{accessanalyzer.ServicePackage(ctx), …}`. The generator reads `names_data.hcl` (`data.ReadAllServiceData()`) and includes a service only if `internal/service/<pkg>/service_package_gen.go` exists, so service-level metadata and per-service generation are two inputs to one provider-level list. The same generator writes `internal/sweep/service_packages_gen_test.go`.

## The ServicePackage contract

`internal/conns/conns.go`:

```go
type ServicePackage interface {
	FrameworkDataSources(context.Context) []*inttypes.ServicePackageFrameworkDataSource
	FrameworkResources(context.Context) []*inttypes.ServicePackageFrameworkResource
	SDKDataSources(context.Context) []*inttypes.ServicePackageSDKDataSource
	SDKResources(context.Context) []*inttypes.ServicePackageSDKResource
	ServicePackageName() string
}
```

Each service's generated `service_package_gen.go` implements it, and the file carries more than registration:

| Method / function | Source of its data | Consumer |
|---|---|---|
| `FrameworkResources`, `SDKResources`, `…DataSources`, `…ListResources`, `EphemeralResources`, `Actions` | annotations | provider `initialize()` |
| `ServicePackageName()` (e.g. `names.ECS`) | `names_data.hcl` | context, client cache, tags, smarterr, logging |
| `NewClient(ctx, config)` | `names_data.hcl` (SDK package, endpoint resolver) | `conns.client[T]` via type assertion |
| `withExtraOptions` hook | hand-written method if present (21 services have `service_package.go`) | `NewClient` |

`service_endpoint_resolver_gen.go` (same generator) supplies `newEndpointResolverV2` and `withBaseEndpoint` from service data. So annotations feed the registration lists and `names_data.hcl` feeds everything else in the file. Clients depend on the service package existing in the list and on `ServicePackageName()`, not on resource registration.

## What the provider reads from each registration

SDKv2 (`internal/provider/sdkv2/provider.go`, `initialize`, ~537-800) and Framework (`internal/provider/framework/wrap.go`, `newWrappedResource`, ~500):

| Field | Use |
|---|---|
| `TypeName` | key in `ResourcesMap`/`DataSourcesMap` (SDKv2); returned by the Framework wrapper's `Metadata()`; duplicate is a startup error |
| `Factory` | called once to build the resource |
| `Name` | passed to `conns.NewResourceContext` |
| `Region` | if override enabled: inject the `region` schema attribute, add validate/default/force-new/set-in-state interceptors, add a no-op Update if missing; import-region interceptor depends on `Identity.HasInherentRegion()` |
| `Tags` | if enabled: transparent-tagging, `tags_all`, required-tags interceptors |
| `Identity` | if attributes exist: build the resource identity, apply `MutableIdentity` behavior, add the identity interceptor |
| `Import` | `CustomImport` requires the resource to define an importer (startup error otherwise); `WrappedImport` requires it not to, and installs an ARN/singleton/custom-inherent-region/parameterized importer chosen from `Identity` |

The inner Framework resource's own `Metadata` is never called. The embedded base `framework.ResourceWithConfigure.Metadata` panics by design ("This method is implemented in the wrappers", `internal/framework/resource_with_configure.go:20`); `wrappedResource.Metadata` returns `spec.TypeName` (`wrap.go:604`). Registration is the only source of a Framework resource's type name. The factory is called when wrapping (`wrap.go:530`), so the inner resource exists at provider startup.

## The friendly name

`Name` has three consumers across two phases:

| Consumer | Phase | Use |
|---|---|---|
| `internal/smerr/smarterr.go:90` | runtime | becomes the `smarterr.ResourceName` keyval |
| `internal/provider/interceptors/info.go:26` | runtime | `InfoFromContext` returns it; callers interpolate it into error strings like `"updating tags for %s %s (%s): %s"` |
| `tagstests/main.go:198,264` plus three templates | generation | fixture directory path `testdata/{Name}/` |

Both runtime reads come from the context value written by `conns.NewResourceContext`; neither feeds the other. At runtime the friendly name is diagnostic-only, read by nothing that makes a decision. At generation time it is a filesystem path component: `identitytests/resource_test.go.gtpl`, `tagstests/resource_test.go.gtpl`, and `tagstests/data_source_test.go.gtpl` emit `testdata/{Name}/`, and the 685 checked-in fixture directories holding all 4,063 `testdata/*.tf` files are named this way (`kinesis/testdata/Stream/`, `.../StreamConsumer/`). A `Name` differing from today's value moves those directories and breaks tests referencing the old path, in addition to changing error text. This affects the ~9-16% of names that do not derive from the factory name (see [registration.md](registration.md)).

Known bug: in `InfoFromContext`, when `typeName` is empty the fallback assigns `resourceName` the `aws_<service>_<thing>` string instead of `typeName`. Harmless today because registration always sets `TypeName`.

## Other places type names live

These do not pass through registration but repeat the same public strings:

| Place | Count |
|---|---:|
| `resource.AddTestSweepers("aws_…", …)` | 390 |
| `awsv2.Register("aws_…", …)` | 371 |
| `sweep.go` files | 196 |
| `"aws_…"` literals in non-test, non-generated service code | 4,665 |
| Docs: `website/docs/r` / `d` / `list-resources` / `ephemeral-resources` / `actions` | 1,722 / 680 / 245 / 11 / 12 |

Sweeper registration is hand-written and keyed by type-name strings, independent of annotations. Docs filenames are a second independent source of every type name.

## Validation that already runs

- Startup `initialize` rejects duplicate type names and inconsistent `CustomImport`/`WrappedImport` settings.
- `TestProviderInit` (`internal/provider/sdkv2/provider_test.go`) builds the provider, calls `InternalValidate()`, and runs `validateResourceSchemas(ctx, slices.All(servicePackages(ctx)))`.
- `.ci/providerlint` has 11 custom type-aware `go/analysis` passes.

## Registration is not done by init()

52 `func init()` exist in `internal/service`, all in `_test.go` files, registering error-check functions via `acctest.RegisterServiceErrorCheckFunc`. Zero in production service files. Sweepers now use an explicit `func RegisterSweepers()` calling `awsv2.Register(...)` (`internal/service/ec2/sweep.go:28`). Production registration by `init()` has been removed twice: from this subsystem and separately from sweepers (see [history.md](history.md)).

## Supporting data structures

`inttypes.ServicePackageSDKResource` (`internal/types/service_package.go:166`) has `Factory`, `TypeName`, `Name`, `Tags`, `Region`, `Identity`, `Import`. `inttypes.Identity` (line 190) exposes `Attributes []IdentityAttribute`, `IsARN`, `IsSingleton`, `IDAttrShadowsAttr` as plain fields.

## What a replacement must preserve

1. Every service package appears in the provider-level list, with `ServicePackageName()` and `NewClient`.
2. For each resource kind, the provider receives the same `inttypes.ServicePackage*` values: `Factory`, `TypeName`, `Name`, `Region`, `Tags`, `Identity`, `Import` (fields vary by kind).
3. `TypeName` is the only source of Framework type names and the map key for SDKv2.
4. `Name` reaches smarterr and the info interceptor through the context, and names the `testdata/{Name}/` fixture directories at generation time.
5. Optional kinds (ephemeral, list, actions) keep being detected per service.
6. Startup validation (duplicates, import consistency) keeps running, or moves to an equivalent test.

None of this requires annotations or a particular generator. Byte-identical `service_package_gen.go` output shows the provider sees no difference.
